## 結果先行

v0.2.4 確實封閉 v0.2.3 的兩個 blocker：

- `CLOSURE-EDGE-SCOPE-01`：CLOSED/PASS；
- `ORACLE-DECL-FAMILY-01`：CLOSED/PASS。

但它不能晉級，因為又暴露兩個互相獨立的介面義務：

1. normative `judgments` 沒有定義 `GenericEnvelopeShape`，後續 `SupportedEnvelopeHeader` 與 `UnsupportedEnvelope` 卻引用它；`base_envelope_shape` 又位於宣告為 normative source 的 judgments 之外。這是 judgment dependency graph 不閉合。
2. `admissibility.advice` 仍是未派生的 free text。有效測試證據可讓 accepted record 同時宣稱「per-n truth table」，又保留 uniform、無 advice generator、無 answer access、ledger advice=0 與 generation output=0。這是 declaration／ledger 矛盾，不是 correctness bypass。

兩項都不代表程式錯誤求解，也不具有 P/NP 蘊含。AEREC 選擇器因此保留 v0.2.4 的 153 個 frozen paths，不原地修文，選擇 `no-change` 並要求另起後繼版本。

觀察到 **17.85×** 驗證吞吐改善。這只來自移除重複全樹索引／讀取，不是 SAT solver 加速，也不是漸近複雜度主張。

工程適應也從「每版複製整支探針」改成共用 probe engine + version profile。v0.2.4 只宣告新 pins、路徑、scope gate 與 oracle declaration 回歸，之後可更快承接新版本，同時保留 no-change 約束。

## 後繼版最小封閉條件

### Normative judgment graph

1. 把 `OpaqueLeaf`、`GenericEdgeShape`、`GenericEnvelopeShape`、`MalformedEnvelope`、`SupportedEnvelopeHeader`、`SupportedEdgeRelation`、`UnsupportedEnvelope` 全部放入同一 normative judgments map。
2. 每個 judgment 使用 machine-readable `depends_on`，所有引用必須存在；不允許 prose-only 隱式定義。
3. 新增 symbol dependency closure 測試：0 unresolved symbols，且每個分類出口有唯一 result/traversal 規則。
4. 保留 future unsupported → UNKNOWN、future supported → FAIL、malformed → FAIL 的現有 executable 行為。

### Advice declaration／ledger consistency

1. 將 free-text `advice` 改成 typed `advice_mode`。
2. 對目前 pinned I0 以 `ExpectedAdviceDecl(family, mechanism)` 導出 exact mode。
3. 雙向核對 `advice_mode`、program quantifier、uniformity、`advice_generator_ref`、observed answer access、ledger advice/generated-table bytes、advice-generation time/output。
4. 增加 mode-only、generator-only、quantifier-only、access-only、ledger-only 的單欄負例，以及 stream/table/2-SAT 正例。
5. 後來的 advice 反例只能放進新版本，不能回寫 v0.2.4 manifest。

完成正確性封閉後，下一個安全的速度迭代是 dependency-closed minimal snapshot：從 manifest pins 與 operational refs 建出最小閉包，而非總讀 497 檔；任何缺依賴仍 fail closed。
