## 結果先行

v0.2.3 的可執行修補本身通過所有本地機械檢查，但不能晉級。阻擋原因不是錯誤接受，而是凍結 closure spec 的量詞範圍不唯一：`edge_shape.expected_type` 寫成「must equal the pinned parent-type/role relation」，卻沒有明說這條 relation 只在 supported `spec_id` 適用。同一個 shape-valid future-type witness 因而可合理得到兩種形式化：

- 全域 relation 讀法：沒有 future parent/role 的 pinned relation，故 `FAIL`；
- supported-only 讀法：先分派為 unsupported，故 `UNKNOWN`。

所以 AEREC 選擇器即使看見 56/56 測試全綠，仍依法選 `no-change`。v0.2.3 的 121 個凍結路徑保持不變；正確後繼是另起 v0.2.4，把 `GenericEdgeShape` 與 `SupportedEdgeRelation` 明確分開。

這是 Definition/interface blocker，不是 P/NP 結論，也不是 admission bypass。

同一 33-fixture corpus、每 fixture 5 次量測：

觀察到的驗證吞吐改善為 **13.36×**。最後加入已裁定 blocker 後的 batch 重跑為 466.945 ms，仍得到 `probe_execution_ok=true`、`promotion_allowed=false`、`selection=no-change-control`。

這個加速來自移除重複的全樹索引與讀取，不是 SAT solver 加速，也不是漸近複雜度主張。目前 optimized path 仍會使用 validator 的內部 snapshot 結構，所以只是工程實驗，尚非穩定 public API。

## v0.2.4 必須封閉的最小介面

1. `GenericEdgeShape` 只檢查所有 spec 共用的 syntactic shape：required members、非空字串、edge 欄位、role 唯一、hash 格式。
2. 完整 generic shape 之後才做 `spec_id` dispatch。
3. unsupported 且 shape-valid 的 envelope 一律 `UNKNOWN` 並阻擋 admission；不要求目前版本的 pinned relation。
4. 只有 supported spec 才套用 version、artifact type 與 `SupportedEdgeRelation(parent_type, role, child_type)`。
5. 將 future-type/nonempty-edge witness 加入凍結測試，並使規格、程式、manifest 三者只能導出同一狀態。
6. 保留 v0.2.3 bytes 與 FAIL receipt，不以原地修文抹除失敗歷史。
