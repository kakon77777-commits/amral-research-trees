## Why this round can be held to a higher standard than the last three

A-U.2d.3 takes exactly **one** external input — a Diophantine exponent for
`α = log2/log3` — and derives everything else from it:

> `ρ★ = 4.1164`,  `μ★ = ρ★ + 1`,  `θ★ = 1/μ★`,  `σ★ = 1/(1 + θ★)`

`4.1164` is a terminating decimal. So `μ★ = 12791/2500`, `θ★ = 2500/12791` and
`σ★ = 12791/15291` are **exact rationals**, and the shipped JSON publishes 100
digits of each. That is the RUN-027 situation again — a quantity the artifact
computes in floating point which is in fact rational — except that here it is not
an incidental observation but the spine of the round.

All three are right to every published digit.

## The two coefficients, and a probe that can reject a neighbour

Sections 9 and 16 do not merely quote constants. They quote **second-order
coefficients of asymptotic expansions**:

> `q⁺ ≳ c₀·y/q + c₁·y/q^{3/2} − q`   and   `q ≥ A/η_β + (κ_rot/η_β^{3/2})·√A`

A wrong *first* coefficient is loud — the expansion stops tracking. A wrong
*second* coefficient is quiet: the leading term still dominates and everything
looks fine. Checking that `c₁` equals `ln2·κ_rot/η_β²` to a hundred digits tests
the symbols, not the expansion.

The discriminating probe is the **scaled residual**, which tends to zero exactly
when the coefficient is right:

| | round's value | value 1% off |
| --- | --- | --- |
| §9 residual at `q = 10¹²` | `1.73e-7` | `−0.00706` |
| §16 residual at `A = 10¹²` | `3.00e-8` | `−0.00500` |

The round's residuals fall by a factor of `10⁴` from `q = 10⁴` to `10¹²`; the
perturbed ones **converge to a nonzero constant** instead. Both coefficients are
right, and the check that says so would have said otherwise about a value 1%
away. That is the difference between confirming a number and testing a claim.

## The continued fraction, with no logarithm evaluated

The artifact's convergents come from mpmath's floor-and-reciprocal loop at 100
digits. Recomputing them at higher precision would agree — and would prove
nothing about method, only about arithmetic.

So they were recomputed with **no floating point at all.** Every step of the
continued fraction of `log₂3` is `⌊log_u v⌋` for exact rationals `u, v` lying in
the multiplicative group generated by 2 and 3, so each partial quotient reduces
to comparing `2^A` against `3^B` — integers. **16 partial quotients certified
this way, up to denominator 10,781,274**, in agreement with the artifact on every
shipped row.

**Where that stops is measured, not asserted.** The integers grow with the
denominators, and the seventeenth term was still running after 200 further
seconds when the budget cut it off. So the run reports 16 certified and says
plainly that the three rows beyond it (`q` up to 397,573,379) are **cross-checked
at four times the artifact's precision, not certified**. A bound is not a
measurement, and a cutoff crossed silently is worse than one named.

The independence of that route is itself measured: the gate **counts the integer
comparisons it performed** and refuses if the count is too low. That field exists
because the drill needed to be able to break the claim — see below.

## Looked for and not found

**The artifact defect of items 35, 45 and 46 does not recur.** The shipped JSON's
top-level keys and row keys match what the shipped script writes, exactly, in
both directions. Three occurrences in a row does not make a fourth, and reporting
a streak that has broken would be worse than never having counted it.

**And a specific, quantitative hypothesis about the Diophantine input was raised
and refuted.** The value `4.1164` is close to `μ(ln 3) ≤ 5.1163051 − 1`, a
published bound on a *different* number, and the round would collapse
quantitatively if that were the source: `θ★` would move from `0.19545` to about
`0.116`, taking every exponent with it. Fan–Queffélec–Queffélec's own text
settles it — they give Rhin's bound for `α = log2/log3` as `ρ ≤ 7.616` and state
that Wang and Wu improved it to `ρ ≤ 4.11633052`, for that same `α`. The round's
value is correctly sourced, and `4.1164 > 4.11633052` by `1737/25000000` — so
"conservatively" is right too, checked as exact rationals.

A web search summary said otherwise. **A search summary is not a source.**

## Finding 1 — one digit, in one constant, and a mechanism for the rest

`η_β = 1/(6 ln 2)` is published to 100 decimals; the hundredth is `8` where the
true value has `7` followed by `4`. Confirmed at 2000 digits. Same class as item
45 (RUN-027), second occurrence, and far milder — one digit in one of four
transcendental constants, the other three being correctly rounded.

The per-row `primitive_error = p − βq` is the interesting half. It is published
to **100 significant digits at every convergent** while the computation behind it
supports between **83 and 100**, and the shortfall is not arbitrary: it is the
cancellation of subtracting two quantities of size `βq` to leave one of size
`1/q⁺`. That costs about `log₁₀(β·q·q⁺)` digits — which predicts the measured
agreement **at every row, to within 2.0 digits, always conservatively**.

That prediction is a check in the gate, not a remark in this file. "Over-published"
is an adjective; `100 − log₁₀(β·q·q⁺)` is something a reader can re-derive.

The two capacity fields are unaffected — no cancellation, and correct at every
published digit.

## Finding 2 — the load-bearing citation names a different paper

The notes cite:

> Lihong Wang, Qiang Wu, *On the irrationality measure of `log₂ 3`*, Journal of
> Number Theory **142** (2014), 264–273, DOI: 10.1016/j.jnt.2014.03.007.

Crossref, for that DOI: title **"On the irrationality measure of log 3"**,
authors **Qiang Wu, Lihong Wang**. Volume, pages, year and DOI match exactly. The
title does not, and the authors are reversed.

`log 3` → `log₂ 3` is a one-character slip, and in most papers it would be worth
a footnote. Here it is worth more, for one reason: **it is precisely the
substitution that makes the citation self-justifying.** This round's entire
quantitative content rests on the exponent applying to `log2/log3` rather than to
`ln 3`, which are different numbers with different literatures. A reader who goes
to check that — the one check that matters — finds the title already asserting
it, and stops.

**The exponent is fine.** It applies to `log2/log3`, established above from
Fan–Queffélec–Queffélec directly rather than from the misstated title. What fails
is the citation, at exactly the point where a reader would rely on it.

Not established: whether that paper itself contains the `log2/log3` exponent, or
whether Fan–Queffélec–Queffélec's reference is a different Wang–Wu work. The
publisher returns 403 and the survey's bibliography was not retrievable. Matching
volume, pages and DOI make it the same paper; its contents were not read, and
this run does not pretend otherwise.

## The instrument

**Drill 20/20 by the check named for each, both controls clean, no malformed
mutations in the final pass.** Four things it found are worth stating, because
three of them were defects in my own tooling and one is a new category.

**A defect that changes no number at all.** D6 swaps the integer-certified
continued fraction for the high-precision one. Every partial quotient it produces
is *identical*, so every field in the report agrees — including the check that
the two methods agree, which becomes a comparison of a thing with itself. Nothing
in the design could see it. The gate now counts the integer comparisons it
actually performed, and that is the only field that moves. **The independence
claim became measurable precisely because the drill had to be able to break it**;
before that it was a sentence in a docstring.

**The restore control fired, and it was right.** `read_text` followed by
`write_text` translates LF into CRLF on Windows, so the drill was rewriting every
line of the file it had just promised to restore. The byte-exact control caught
it on the first full pass. That control has been quiet for six items; this is
what it was for. The harness now works in bytes. (The same round trip is in
`src46_drill.py`, which stayed green only because its gate file was already CRLF.)

**A list the gate reported and gated on that no input could fill.** The exponent
chain's `wrong_digits` filtered for a verdict of `WRONG` — and the shared
comparison routine only ever returned `OVER-PUBLISHED`. The empty list looked
like a clean result for as long as nobody asked what would put something in it.
Fixed by drawing the distinction properly: an exactly-rational quantity has no
precision excuse, so a mismatch beyond last-digit rounding is simply wrong.

**Two near-misses in the accusing direction, on the same comparison.** Deciding
whether a published decimal is *wrong* or merely *rounded* went wrong twice while
this file was being written: first by comparing against a truncation, which calls
a correctly-rounded last digit an error; then by reading the reference digit *at*
the last published position instead of the one *after* it, which misses the carry
— `…173219729` correctly rounds to `…17322`, and reading the `1` rather than the
`9` calls that wrong. Both would have published a finding against correct
arithmetic. There is now one implementation, doing exact rational rounding once.

**Three defects were re-aimed after the pre-flight named them, not the checks.**
`want=2` selected the same two convergents the correct call does; slicing that
filtered list from the front did too, because it has exactly two entries; and
flipping the sign of a quadratic root changed nothing, because **both** roots
solve the quadratic. Each would previously have been scored as a check that
missed. This is the second item running where the pre-flight paid for itself.
